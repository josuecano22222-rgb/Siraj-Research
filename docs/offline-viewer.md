# Offline basemap viewer prototype

This is the administrative package builder. For the optional, smaller interactive download workflow, see `docs/offline-map-packs.md`. No imagery is supplied.

## Administrative offline package prototype

An administrator can build a **basemap-only** ZIP from a trusted, licensed local raster pack using the Python module below. This is a local command, not a Frappe API. Bounds are west, south, east, north in degrees, limited to Web Mercator (approximately ±85.0511° latitude); west greater than east crosses the antimeridian. The output must not already exist. Example only, with paths and bounds chosen by the administrator:

```sh
python -m siraj_research.utils.offline_viewer /private/path/aerial.mbtiles /private/path/area.zip \
  --bounds 43 32 45 34 --minzoom 4 --maxzoom 10 --confirm-redistribution-rights
```

The explicit flag is the administrator's confirmation that the source license permits distribution to disconnected devices. Confirm permitted area, resolution, retention and required attribution before creating or sharing any package. This command does not download imagery and must never be used to scrape public tile services. The source and output paths must be protected; the ZIP contains imagery in ordinary unencrypted files. Share only with authorized people using an approved secure transfer, and protect the extracted files and device. Temporary SQLite files are created in the operating system's temporary directory, whose storage and backups must also be suitable for the imagery. Interrupted or killed processes may leave temporary or partial files for an administrator to remove securely. No automatic revocation or expiry is provided.

Extract the ZIP completely and open `index.html` on the device. The viewer pans and zooms, fits the selected area, accepts decimal coordinates (including Arabic and Persian digits), shows clicked coordinates, and provides approximate distance and polygon-area measurements with undo and clear. Measurements use spherical approximations, are not survey-grade, and may be misleading for very large or self-intersecting polygons; changing modes clears the current geometry. Map controls support English and Arabic; the experimental record panel is currently English only. The ZIP contains no SIRAJ records and does not edit or sync them. The panel can manually open a separate compatible local snapshot, subject to the limitations below; it does not provide the full Explorer. It makes no intentional internet requests. It uses local Leaflet assets and packaged tile images; some browsers or device policies may restrict local files, and mobile behavior has not been verified. Missing tiles produce empty areas. Tile availability and resolution depend on the provided pack, and a requested area can contain only partial coverage. The package contains no generalized fallback unless that fallback is included in the supplied tiles.

Exports are limited to 25,000 possible tiles and 200 MiB of actual tile payloads, with additional disk space needed for SQLite, the ZIP, extraction, and filesystem overhead. These are not full disk, time, concurrency or per-user quotas. Package creation is synchronous and is not intended to run concurrently on a live Frappe web worker. It is not a sandbox for malicious databases or an authorization layer. **An experimental read-only local snapshot viewer exists, but an authorized Frappe export and synchronization are not implemented.** Do not expose this tool as a web endpoint without a reviewed rights, security, quota, lifecycle and privacy design.


A synthetic package was smoke-tested with Chromium from a local `file://` URL. No real imagery, mobile device, Frappe integration or production-scale workload has been verified.

## Experimental local record viewer

New packages include an optional **Offline records** panel that accepts a manually selected local JSON snapshot, searches identifiers, filters types and navigates incoming/outgoing links without server requests. Packages themselves contain no records, and there is currently **no Frappe export**, authentication, permission recheck, editing, synchronization, conflict detection, encryption, expiry enforcement or revocation. The file can contain sensitive, unencrypted identifiers. Open only files the operator is authorized to possess; protect the file, device, backups and transfers. The viewer does not verify a file's origin or ensure the user is authorized. Closing the panel's snapshot clears its own in-memory display, not the original file or OS/browser caches. An unsigned file date is untrusted and is not echoed in the trust-status message.

The strict input has `version` 1, a nonempty `created_at` string, `nodes` of `{doctype, name}`, and `edges` of `{source: {doctype,name}, target: {doctype,name}, type}`. Nodes are limited to Person, Institution, Place, Source and SIRAJ Research Event; legacy conflicting `Event` is deliberately excluded. No labels, coordinates, fields or attachments are imported. Maximum file size is 2 MiB, 2,000 nodes and 4,000 edges; duplicate nodes, unknown properties/types, invalid values and dangling endpoints reject the entire file. This format does not establish permission filtering; do not prepare a real data file until a separately reviewed export exists and use is explicitly authorized. The panel is not wired to the online Explorer. Previously generated ZIPs do not gain this feature and must not be overwritten.

A separate experimental v3 signed format can be verified only when a trust policy has been independently provisioned; no default policy or production exporter exists. Signed files are plaintext and offline identity, current permissions and revocation cannot be guaranteed. The earlier v1 manual format remains explicitly UNVERIFIED. See `qa/signed-snapshot-prototype.md` before any real use.

The experimental record panel builds an in-memory adjacency index after validating the entire snapshot. Opening an identifier shows incoming/outgoing linked identifiers and their count, with at most 100 relationship buttons rendered per page and previous/next controls; a self-link appears once. Search/type filtering still lists at most 100 records. Missing endpoints reject the whole file rather than exposing a dangling link. This is not a full offline Explorer: only the snapshot's identifiers and relationships are available, no Place hierarchy or field details are inferred, and export, encryption and real-data trust provisioning remain disabled pending review/approval.
