Real-environment testing must therefore be coordinated with the owner. Production load testing is not authorized. Synthetic unit tests, single-browser smoke tests and static code review are not load measurements.

## Candidate workloads and risks (hypotheses, not measured bottlenecks)

- Geographic, relationship and Structures APIs: paged visible-record scans plus document-level permission checks; response serialization and browser rendering grow with records. Offset paging is not a transactionally consistent snapshot; concurrent changes can alter results. Optional relationship evidence loads each visible relationship document (N+1 risk).
- Tree navigation and reports: permission-filtered pages and parent/link checks; output varies with custom permission hooks and user permissions.
- Local tiles: each request checks access, pack metadata and reads SQLite; limits are per IP, not global quotas. Offline area download can issue up to 512 sequential tile requests in its UI; view-only users can request individual tiles outside that UI. Shared NATs and concurrent viewers need measurement.
- Check actual deployed background workers, scheduled jobs, database indexes/slow-query log and other apps; no active SIRAJ scheduler is declared in the reviewed app hook, which does not prove the whole site lacks jobs.

## Bounded browser probe (implemented, not run)

`docs/qa/load-probe.js` defines an opt-in `sirajLoadProbe` in an already authenticated browser tab. It does not run on loading and stores no credentials or response bodies. It uses fixed same-origin **GET** routes for geography, relationships, people Structures, the relationship report, and Place tree root or a separately supplied existing Place parent; it has a maximum of five concurrent requests, 20 total requests, 16 MiB consumed per response, and a 60-second overall browser-side deadline. These caps do **not** bound database work, server processing after a client abort, side effects of custom hooks or load from other traffic. Larger-scale and mixed-user tests need a separately designed, approved workload. The browser does not collect server/DB resource usage, and HTTP 200 alone is not a correctness or permission result.

**Do not run on the working site until the owner separately authorizes a test window, reviews expected query volume and stop thresholds, and has a monitoring/recovery plan.** After the update has separately been approved and applied, the authorized operator may open the Frappe site while logged in as the approved role, inspect the script at `apps/siraj_research/docs/qa/load-probe.js`, and paste its complete contents into that same tab's developer console. Only paste code after reviewing it and only on the intended site. Then start with a single request:

```js
await sirajLoadProbe('geography', 1, 1)
```

Additional calls, such as `await sirajLoadProbe('relationships', 2, 4)` or `await sirajLoadProbe('structures', 2, 4)`, require the approved workload plan. The added `relationship_report` uses the standard query-report endpoint with prepared results bypassed; server-side report errors may be logged and custom report code/hooks may have side effects. `place_tree_root` requests the Place root and `place_tree_parent` takes a fourth argument containing an already-existing parent name. Even though results omit it, a parent name can appear in browser history/devtools, proxy or server logs; protect those logs. A non-200 response stops scheduling new requests, but in-flight server work can continue. These additions have only synthetic tests and have not been run on the site. The result lists status counts, success throughput, response bytes and client-observed p50/p95/p99; small samples cannot support a meaningful p95/p99 and are smoke checks only. Record revision, route, role label, concurrent requests, duration, browser, anonymized dataset scale, server/database CPU/memory/IO, query metrics, errors and competing workload. Stop on the agreed thresholds or unexpected errors; aborting the tab does not guarantee server work stops. Do not paste response bodies, records, session cookies or credentials. No measurements have yet been collected.
