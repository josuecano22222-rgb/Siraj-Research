# Coordinate map for Desk forms

This first update adds a shared map preview to Desk forms with fields whose **fieldnames** are `latitude` and `longitude`. It is a dynamically rendered form control, not a new saved GeoJSON field. It respects the fields' Frappe read/write/hidden status: if either field is hidden the map is removed, and selecting or clearing coordinates requires write access to both. Embedded child-table rows are not supported. The feature does not alter other apps' field definitions or permissions.

For a pair of writable **Data, Small Text, Text or Long Text** fields, typing valid decimal degrees immediately moves the marker without rewriting the entered text. Click the map to set both fields, or clear both; save the document normally. Arabic-Indic and Persian digits and the Arabic decimal separator are accepted in the form preview. Text is stored by the underlying fields, not the map, and may be limited by their configured length (Frappe Data defaults to 140 characters). The map itself uses JavaScript numbers, so its displayed position is an approximation; selecting a map point writes the precision available from the browser. Server-side validation and other apps' own rules still apply. The preview checks ranges but does not itself prevent saving invalid text.

The local Natural Earth world basemap loads by default. It is generalized, not street-level. The optional OpenStreetMap street layer requires an explicit click and sends the viewer's IP address and viewed map area to that provider. No third-party map tile is loaded automatically. It may be unavailable if network or security policy blocks it. The map provides zoom controls and accepts coordinate input as a keyboard alternative to map clicking.

## Important release limitation

The six SIRAJ coordinate pairs currently installed on the existing site are **Float**, not text. For non-text coordinate pairs the current update shows a preview only and will not write selected points. It does not change their field types or database columns. A local, unreleased prototype changes SIRAJ's fields to Data, but that schema change is **not yet validated or deployed**. Once safely migrated, future text entries can retain more decimal digits; precision already lost through numeric storage cannot be recovered. Converting existing columns has data, defaults, and rollback implications and must be rehearsed with a restore-tested backup.

The unresolved SIRAJ/Frappe Event collision remains a site-wide blocker. Do **not** run `migrate`, `reinstall`, or the synthetic-data command to activate coordinate changes. The form map is not a fix for that collision. No live Frappe or role-permission test has been performed for the map. Local tests use a mocked form and map. The geographic Explorer still treats `(0, 0)` as ambiguous for historical numeric records and excludes it, even though the form map can preview it. Correcting that requires a deliberate legacy-data policy.
