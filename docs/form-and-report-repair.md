# Form and report repairs

Frappe automatically discovers a DocType's `<doctype>.js` file beside its JSON. There are only three such form scripts in this app: Person, Military Unit and Relationship. The other DocTypes use metadata and Python controllers where implemented; they do not have a missing switch that enables nonexistent scripts. Browser scripts should provide presentation and navigation only. Permissions, validation and state changes belong in Frappe's server-side APIs and controllers.

Six DocTypes previously declared Server Actions under `siraj.api`, but no such module exists in this app. Those broken actions have been removed. For Person, Institution, Place and Event there is a native **Open geographic explorer** route action. It opens the general explorer, not a focused marker. Automatic duplicate detection and a custom merge operation are not implemented; removing their broken buttons does not implement them. The standard Frappe rename/merge facility, where enabled and authorized, has its own permissions and semantics. Back up and review links and research records before any merge.

The Relationship form's swap button now edits its actual subject/object fields. Saving still goes through Frappe's permission checks and validation; the server derives `direction` from Relationship Type rather than trusting a browser value. The Military Unit button opens the existing Military Force Structure report with a unit filter. All three reports now use actual schema fields and list plus document permissions; relationship endpoints and unit parents are withheld when the user cannot read them. The quality report counts only visible records. These checks can require one document permission check per record and may be slow on very large datasets.

The explorer's document-level permission call now uses the Frappe v15 `throw` keyword. Prior to this change any non-empty result would raise a `TypeError`. Site-specific exceptions still require the server traceback; a browser HTTP status alone is not a diagnosis. Socket.IO is a separate bench service and is not repaired by these application changes.

After updating, run site migration to synchronize the standard DocType actions and reports, build assets and clear cache. Restart the bench's web workers if they keep serving old Python code. Run the local unit suite with `python3 -m unittest discover -s tests -v`; also test on a Frappe v15 site with actual records and restricted users. The unit suite uses a stub rather than a running Frappe/database server.
